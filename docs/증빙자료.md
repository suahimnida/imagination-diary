## **프로젝트 초기 설계단계에서 사용된 레퍼런스**
<img width="595" height="659" alt="image" src="https://github.com/user-attachments/assets/3cbb5fe8-4d1b-4809-bb2b-ab420784fcf1" />

## **레퍼런스와 함께 첨부된 설명**
- 구성은 전체적으로 주어진 레퍼런스와 비슷하게 하되 아래의 사항을 따른다.

1. "기본 페이지"는 지금 보이는 페이지는 사이트에 진입하면 맨 처음에 보이는 기본 페이지이다
2. "기본 페이지 설명"의 1번의 네모 안에 있는 텍스트 "Imagination"을 클릭하면 현재 보이는 기본 페이지로 이동한다
3. "기본 페이지 설명"의 2번의 네모 안에 있는 텍스트 "Diary"를 클릭하면 "Diary 페이지"로 이동한다
4. "기본 페이지 설명"의 3, 4, 5번 네모 공간은 기존에 만들어져있던 이미지들을 랜덤으로 보여주는 칸이다
5. "Diary 페이지 설명" 의 1번 네모의 안의 버튼 안에 있는 "AI"라는 글자를 "오늘의 일기쓰기" 라는 문구로 바꾼다
6. "Diary 페이지 설명" 의 1번 네모의 안의 버튼을 클릭하면 일기를 작성하는 페이지로 넘어간다
7. 일기를 작성하는 공간은 레퍼런스가 없으면 앞의 레퍼런스와 어울리는 분위기의 페이지로 구성한다
8. 페이지에는 제목과 날짜를 입력하는 칸, 내용을 입력하는 칸으로 구성한다
9. 일기를 작성하는 칸 밑에는 "일기 작성 완료"라는 버튼을 만들어둔다
10. "일기 작성 완료"을 클릭하면 이미지를 생성하기 위해 설문 페이지로 넘어간다.
11. 설문 페이지에는 카툰, 반실사, 수채화, 카툰, 애니, 3D 등의 키워드들 중 1~5개를 선택 가능하도록 한다
12. 선택된 키워드들을 조합하여 Gemini API가 일러스트를 생성한다
13. 생성된 일러스트는 "Diary 페이지"와 "기본 페이지"에서 확인 가능하다
14. "Diary 페이지 설명"의 5, 6, 7, 8 네모 칸은 일기를 정렬하는 대략적인 위치이다
15. "Diary 페이지 설명"의 2번 네모 안에는 입력한 날짜가 오도록, 3번 네보 안에는 제목이 오도록, 4번 네모 안에는 생성된 일러스트가 나오도록한다
16. "Diary 페이지 설명"을 참고하여 향후 생성되는 일기와 일러스트의 정렬을 5, 6, 7, 8번 네모 순서처럼 정갈하게 배치한다
17. "Diary 페이지 설명"에서 5, 6, 7, 8번 네모 중 하나를 선택하여 네모 안의 범위를 클릭하면 다른 페이지로 이동하고, 작성한 일기 제목과 날짜, 일기 내용, 일러스트를 볼 수 있게한다.

1. 기능 요구 사항

1) 프로젝트 초기화 및 구조 구성
- 프로젝트 폴더를 생성하고 기본 구조를 구성한다.
예: index.html, css/, js/, api/, images/, requirements.txt
- GitHub 저장소를 생성하고 커밋 이력을 남긴다.

2) 프론트엔드 화면 구현 (바닐라)
- AI 코딩 도구를 활용해 메인 및 추가 페이지/섹션을 구현한다.
- 페이지/섹션 간 네비게이션(이동)을 제공한다.
- 기본 레이아웃과 스타일을 적용한다.

3) 반응형 적용 및 확인
- 모바일/태블릿/데스크톱에서 레이아웃이 깨지지 않도록 조정한다.
- 최소 2가지 화면 크기에서 직접 확인한다.

4) AI 기능 UX 최소 기준
- 사용자 입력을 받는 UI(폼/텍스트 입력 등)를 제공한다.
- AI 결과를 화면에 표시한다.
- 아래 실패 처리 중 최소 1개 이상을 사용자에게 안내 메시지로 제공한다.
빈 입력(필수값 누락)
API 오류(4xx/5xx)
지연/타임아웃(응답이 늦을 때)

5) AI API 연동 (백엔드: Vercel Serverless Functions - Python)
- api/에 Python 함수(엔드포인트)를 구현한다.
- AI API(OpenAI, Claude 등) 호출 후 결과를 반환한다.
- 필요한 패키지를 requirements.txt에 정의한다.
- 프론트에서 fetch('/api/...')로 호출하고 응답을 처리한다.

6) 배포 및 동작 검증 (Vercel)
- GitHub와 Vercel을 연동해 배포한다.
- 배포 URL에서 전체 기능(네비게이션/반응형/AI 기능)이 동작함을 확인한다.
- 문제가 있으면 수정 후 재배포한다.

7) 문서화 및 제출 패키지 구성
- README.md에 핵심 내용을 정리한다(소개/기술 스택/배포 URL/실행 방법/환경 변수).
- 스크린샷 및 AI 코딩 도구 사용 증빙을 준비한다.
- 서비스 기획서를 제출 패키지에 포함한다.

2. 개발 환경
- VSCode에서 실행하여 웹 페이지 생성
- 프론트엔드는 순수 HTML/CSS/JavaScript로 구현한다. (React/Vue 등 프레임워크 사용 금지)
- 백엔드는 Vercel Serverless Functions(Python)를 사용한다. (api/ 폴더)
- AI 기능은 최소 1개 이상 포함한다

3. 제약 사항

1) 보안/운영 안정성
- API 키는 반드시 환경 변수로 관리하고, 코드/README/스크린샷에 노출하지 않는다.
- AI API는 과금/쿼터가 발생할 수 있음을 인지하고, 호출 빈도와 실패 상황을 고려한다.
- 키 유출이 의심되면 즉시 폐기/재발급하고, 노출된 커밋 이력도 정리할 수 있어야 한다.
